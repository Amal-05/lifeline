# M4 risk and preparedness demo

1. Start `docker compose -f infra/docker-compose.yml up --build`.
2. Open `http://localhost:4173/dashboard`, sign in with synthetic demo credentials, and view the synthetic H3 risk cells. Once loaded, the risk layer is cached in browser storage and remains visible offline on that browser profile.
3. Check the household consent box, use only synthetic contact details, and submit. The API stores encrypted contact fields and returns a registration ID and H3 cell only.
4. Run the 30-seed scenario suite with `.venv/Scripts/python.exe -m services.simulator.m4 --seeds 10 --output docs/results/m4-simulation.json`.
5. Run authenticated k6 reads with `docker run --rm -e BASE_URL=http://host.docker.internal:8000 -v C:/path/to/lifeline/infra/k6:/scripts:ro -v C:/path/to/lifeline/docs/results:/results grafana/k6:latest run --summary-export=/results/k6-summary.json /scripts/operations.js`. The checked-in report records both a passing 25-VU local run and the 100-VU saturation limit.
6. Rehearse database recovery with `./infra/backup-restore.ps1 -OutputPath .\backups\lifeline.dump` from PowerShell.

The risk data and contact inputs used in this demo must be synthetic. Do not use the demonstration key or default account in a shared or production deployment.
